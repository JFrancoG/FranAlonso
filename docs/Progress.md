## Verified Bootstrap Baseline

- Host: macOS 26.6 (`25G5065a`). Xcode: 26.6 (`17F112`). Active scheme/test plan: `FranAlonso`.
- The validated Debug build uses the iPhone Simulator 26.5 SDK. Project, app, and test Debug/Release deployment targets are aligned to iOS 26.0 without raising the app minimum.
- App and test targets use Swift language mode 6.0, `SWIFT_STRICT_CONCURRENCY = complete`, and `SWIFT_DEFAULT_ACTOR_ISOLATION = nonisolated` in Debug and Release. This keeps Domain/Data actor-neutral by default while UI-owned types remain explicitly `@MainActor`.
- The app supports iPhone and iPad, with Mac Catalyst, Designed for iPhone/iPad on Mac, and Designed for iPhone/iPad on visionOS disabled.
- Firebase 12.16.0 is resolved through the shared `Package.resolved` file.
- The exact approved Firebase products are linked: Core, Auth, Firestore, Storage, Analytics Core, and Crashlytics. `FirebaseAnalyticsIdentitySupport`, AdSupport, and IDFA capability are absent; `-ObjC` is present as required by the Firebase integration guide.
- The SwiftUI entry point registers an app-owned `UIApplicationDelegate` through `UIApplicationDelegateAdaptor`. Its launch callback calls the concrete `FirebaseConfigurator.configure()` directly; no stored closure, custom initializer, intermediate bootstrap object, or configuration protocol exists. Firebase SDK imports remain under feature-local `Data/Infrastructure/Firebase` paths. Auth, Firestore, and Storage stay unimported until their real adapters are introduced.
- `AppDelegate` lives in its own `App/AppDelegate.swift` file. `Resources` contains the String Catalog, `Assets.xcassets`, the `franalonso.icon` Icon Composer document, and the local-only `GoogleService-Info.plist`; Xcode's synchronized app group preserves their target membership without manual project references.
- Analytics is permanently deactivated in the versioned base Info.plist because Firebase's unavoidable automatic event stream cannot satisfy the accepted closed allowlist; automatic screen reporting and IDFV collection are also disabled. Its Firebase adapter fails closed if asked to enable or log. Crashlytics remains opt-in. The telemetry contracts expose only typed, versioned technical events/diagnostics, gate writes on explicit consent, and absorb adapter failures independently.
- Debug and Release generate DWARF with dSYM files. The final Crashlytics build phase declares the app dSYM, executable, packaged Firebase plist, and Xcode debug-dylib sandbox inputs.
- Xcode recommended settings were accepted manually before 02.1; the resulting `LastUpgradeCheck` and String Catalog symbol-generation settings build without warnings.
- Project Debug and Release configurations enable `SWIFT_TREAT_WARNINGS_AS_ERRORS` and `GCC_TREAT_WARNINGS_AS_ERRORS`; the app and test targets inherit both settings.
- The project contains one application target and one Swift Testing unit/integration target. Xcode discovers twelve enabled `@Test` cases under `FranAlonsoTests`; there is no UI-test target, native UI-test source, or XCTest/XCUITest import.
- Spanish (`es`) is the project and String Catalog source language. `Localizable.xcstrings` uses stable semantic keys documented in `docs/LOCALIZATION_GUIDE.md`; the app consumes Xcode-generated `LocalizedStringResource` symbols with symbol generation enabled in Debug and Release.

## Observed Bootstrap Gaps

- `Resources/GoogleService-Info.plist` remains local, ignored, untracked, parseable, and aligned with the app bundle identifier. A clean clone or CI environment must provision it securely before a Firebase-enabled runtime build.
- Firebase Analytics remains intentionally non-operational. Enabling its SDK-managed automatic events requires either a newly accepted explicit allowlist/ADR or a different adapter that can enforce the existing closed allowlist; ordinary consent alone must not activate Firebase Analytics.
- Crashlytics collection overrides persist across launches. When 02.8 composes telemetry into the app, startup must reapply the owner-controlled consent before any diagnostic API becomes reachable; the current base plist keeps collection off until then.
- Firebase app-delegate swizzling is disabled. Firebase Messaging, push entitlements, notification permissions, background modes, APNs token mapping, visible-notification delegation, and silent-notification callbacks are intentionally not added in 02.6; if Messaging or Firebase Auth phone flows are introduced later, their required application-delegate callbacks must be implemented and tested explicitly.
- No live controlled Crashlytics event was sent: automatic collection is intentionally disabled and the official Xcode MCP surface cannot perform the required debugger-detached launch. The local dSYM bundle, UUID match, packaged plist, and synchronous build-phase validation are complete; dashboard receipt remains an explicit opt-in operational smoke check and Crashlytics must not be described as live until it succeeds.
- No SwiftData container or dependency composition with `AppDependencies`/`AppEnvironment` exists yet; these belong to subphases 02.7 and 02.8 respectively.
